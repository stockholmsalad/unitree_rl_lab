# 탐색적 후속 실험 v3 — 예측 지평을 노후화 범위에 맞춘다

**작성 2026-09-08 11:40, 학습 시작 직후·결과 확인 전.**

## 0. 이 문서의 지위

**이것은 사전 등록된 확정 실험이 아니다.** 사전 등록 v2 의 결과 동결일(2026-09-07)이
지난 뒤에 설계되었고, v2 게이트 4 의 결과를 **보고 나서** 도출되었다. 따라서:

- 논문에서 **탐색적(exploratory) 후속 실험으로 명시**하고 별도 절로 보고한다
- v2 의 네 게이트 판정과 **섞지 않는다**
- 그럼에도 판정 기준은 **결과를 보기 전에** 이 문서로 고정한다

## 1. 동기 — v2 게이트 4 가 무엇을 보였나

```
ẑ 블록 절제 시 성공률 낙폭 (어려운 지형, n=5)
  jepa  −0.53 pp    recon +1.05 pp    none −1.64 pp    (시드폭 8.54 pp)
```

정책이 예측기 출력을 **전혀 소비하지 않는다.** 그런데 `jepa_skill` 은 4 시드 전부
0.235~0.277 로 유지되었다 — 예측기는 예측을 학습했으나 정책이 쓰지 않는다.

## 2. 진단 — 두 가지 설계 결함

**(a) 지평 불일치.** 학습 중 관측 노후화는 `d ~ U[0, 25]`(최대 0.5 s)인데 예측 지평은
`jepa_k = 100`(2.0 s)이다. 정책이 필요한 값은 "0.5 s 낡은 관측으로부터 현재"인데
예측기는 "현재로부터 2.0 s 뒤"를 낸다. **답이 질문과 다르다.**

**(b) 예측기가 지연을 모른다.** `jepa_predict(z_e, z_p)` 는 관측이 얼마나 낡았는지(`d`)를
입력으로 받지 않는다(`predictor_in_policy=True` 에서 `cond_dim=0` 강제). `d` 가 에피소드마다
0~25 로 달라지므로 예측기는 **얼마나 앞으로 밀어야 하는지 알 수 없다.** 구조적으로 맞는
답을 낼 수 없으며, 그렇다면 정책이 무시하는 것이 합리적 행동이다.

v3 는 **(a) 만** 시험한다. (b) 는 코드 변경이 필요해 별도 실험으로 남긴다.

## 3. 개입

`jepa_k = 100` → **`jepa_k = 25`**. 예측 지평을 학습 노후화 상한과 일치시킨다.
그 외 전부 v2 와 동일하다 — 교사, 환경, 명령 범위, 하이퍼파라미터, 노후화 주입, 롤아웃.

조건은 `jepa` 하나, 시드 1~3 (n=3).

## 4. 판정 기준 — 결과 확인 전 고정

### 주 판정 — 예측기가 쓰이는가 (게이트 4 재측정)

- 지표: ẑ 블록 절제 시 무결손 성공률 낙폭
- **성공: 낙폭(v3 jepa) 이 조건 내 시드폭을 넘어 0 보다 크다**
- 실패: 낙폭이 여전히 시드폭 안 → **지평 불일치는 원인이 아니다.** 그대로 보고하고
  진단 (b) 로 넘어간다

### 부 판정 — 시간 결손 강인성 (게이트 3 재측정)

- 지표: freeze · latency · lowfps 의 AULC (latency 상한 50 스텝 유지)
- 비교 대상: **v2 의 jepa (n=5)**. 같은 환경·같은 평가 프로토콜이므로 비교 가능하다
- 판정: 격차가 두 실험의 최대 시드폭을 넘을 때만 신호로 인정한다

### 보고 규칙

- n=3 이므로 검정력이 낮다. **양성이든 음성이든 확정 판정으로 쓰지 않는다**
- 주 판정이 성공해도 그것은 "예측기가 쓰이기 시작했다"이지 "성능이 개선됐다"가 아니다.
  두 주장을 분리해 적는다
- 평가는 어려운 지형, 게이트 3·4 만 수행한다(occlusion·blind 는 v2 결과를 인용)
